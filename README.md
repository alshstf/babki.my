# babki.my

**Учёт личных и семейных финансов с фокусом на инвестиции.** Selfhosted-first:
ваши деньги — ваша база данных. Российские брокеры и банки — первый класс:
MOEX-инструменты с купонами и НКД, замороженные активы с честной оценкой,
переносы бумаг между брокерами.

> Статус: pre-alpha, активная разработка. Не готово к использованию.

Что умеет: счета (брокерские, банковские, наличные, кредиты) и общий итог
семьи; журнал операций с правкой, фильтрами и импортом/выгрузкой таблиц;
синхронизация Т-Инвестиций; позиции с ценами Мосбиржи и брокера, прибыль по
правилам страны резидентства; доходность счёта, семьи и бумаги за период;
график капитала; страница бумаги; выгрузка всех данных в JSON.

## Быстрый старт (docker compose)

```bash
git clone https://github.com/alshstf/babki.my && cd babki.my/deploy/compose
cp .env.example .env   # поменяйте POSTGRES_PASSWORD, впишите BABKI_ENCRYPTION_KEY
docker compose up -d
# http://localhost:8080
```

Экран первого запуска попросит **код** — программа пишет его в журнал при
старте, чтобы владельцем стал тот, у кого есть доступ к серверу, а не первый,
кто откроет страницу:

```bash
docker compose logs app | grep setup_code
```

`BABKI_ENCRYPTION_KEY` шифрует токены брокеров, которые программа хранит в
базе (подключение Т-Инвестиций и любой будущий импортёр), — без него бэкап
базы был бы заодно и утечкой рабочего токена. Сгенерируйте свой командой

```bash
openssl rand -hex 32
```

и впишите результат в `.env`. Приложение (`all`, `api`, `worker`) без
корректного ключа не запустится и объяснит в логе, что случилось и какой
командой это исправить; служебные роли `migrate`, `seed` и `version` в ключе
не нуждаются и работают без него.

**Обновление существующей установки.** Эта переменная появилась вместе с
поддержкой автоимпорта из брокера; если инстанс был развёрнут раньше, после
обновления `all`/`api`/`worker` откажутся стартовать, пока в `.env` не
появится `BABKI_ENCRYPTION_KEY` (команда генерации — та же, что выше). Это
осознанный отказ с понятной причиной, а не поломка при обновлении.

## Настройки

Всё задаётся переменными окружения; в `deploy/compose` — через файл `.env`.

| Переменная | По умолчанию | Что это |
|---|---|---|
| `POSTGRES_PASSWORD` | — (обязательна) | Пароль базы; только буквы, цифры и `- _ . ~` — он попадает в адрес подключения |
| `BABKI_ENCRYPTION_KEY` | — (обязательна) | Ключ шифрования токенов брокеров, 64 шестнадцатеричных символа (`openssl rand -hex 32`) |
| `BABKI_ENCRYPTION_KEY_PREVIOUS` | — | Прежний ключ на время его смены (см. ниже) |
| `BABKI_SETUP_CODE` | — (код в журнале) | Код первого запуска, заданный заранее — для автоматической установки |
| `BABKI_PORT` | `8080` | Порт на машине, где открывается программа |
| `BABKI_COOKIE_SECURE` | `true` | Вход только по HTTPS. `false` — если программа открывается по обычному http с другой машины, например в домашней сети (см. ниже) |
| `BABKI_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `BABKI_LOG_FORMAT` | `json` | `json` или `text` |
| `BABKI_AUTO_MIGRATE` | `true` | Обновлять схему базы при запуске |
| `BABKI_METRICS` | `false` | Отдавать метрики для Prometheus по адресу `/metrics` (см. «Мониторинг») |

Без docker приложение читает те же переменные и ещё `BABKI_DATABASE_URL`
(адрес Postgres) и `BABKI_HTTP_ADDR` (адрес, который слушать, по умолчанию
`:8080`).

### Смена ключа шифрования

1. Сгенерируйте новый ключ (`openssl rand -hex 32`).
2. В `.env`: `BABKI_ENCRYPTION_KEY` — новый ключ, `BABKI_ENCRYPTION_KEY_PREVIOUS` — прежний; `docker compose up -d`. Программа шифрует новым ключом и читает старые токены прежним.
3. Перешифруйте сохранённые токены: `docker compose exec app babki reseal`.
4. Уберите `BABKI_ENCRYPTION_KEY_PREVIOUS` из `.env` и выполните `docker compose up -d`.

## Работа за HTTPS

Программа сама HTTPS не поднимает — поставьте перед ней обратный прокси.
Например, [Caddy](https://caddyserver.com) с автоматическим сертификатом
(`Caddyfile`):

```
babki.example.org {
    reverse_proxy localhost:8080
}
```

Вход по умолчанию работает только по HTTPS (`BABKI_COOKIE_SECURE=true`):
браузер отправляет куку входа только по защищённому соединению. Если программа
открывается по обычному http с другой машины — например, только в домашней
сети, — задайте в `.env` `BABKI_COOKIE_SECURE=false`, иначе браузер не сохранит
вход (экран входа так и скажет). Адрес `http://localhost` работает в обоих
случаях. Открывать программу в интернет без HTTPS не стоит: пароль и кука
пойдут открытым текстом.

## Мониторинг

Программа сама каждый день забирает цены, курсы и операции брокера. Чтобы
узнать о поломке, не открывая её, есть два адреса.

- **`/api/healthz/data`** — свежи ли данные, по которым считаются цифры: цены
  Мосбиржи и брокера, курсы ЦБ, цены криптовалют. Отвечает `200` и `{"status":"ok"}` или `503` и
  `{"status":"stale","stale":[…]}` со списком устаревших источников. Входа не
  требует и ничего, кроме этого, не сообщает. Подключите его к своему сторожу:
  например, в Uptime Kuma — монитор «HTTP(s)» на
  `http://<адрес программы>/api/healthz/data`; уведомление (Telegram, почта)
  придёт, когда ответ станет `503`. Источник считается устаревшим, если не
  обновлялся три своих срока подряд — у ежедневного это трое суток.
- **`/metrics`** — метрики для Prometheus и Grafana: последний успех и ошибка
  каждой фоновой задачи, длительность задач и запросов, стандартные метрики
  Go. Выключены по умолчанию, включаются `BABKI_METRICS=true`. Адрес не требует
  входа — не открывайте его в интернет, оставьте доступным только Prometheus
  (сетью или обратным прокси).

Проверка `/api/healthz`, которой пользуется Docker, говорит только, что
программа жива: устаревшие курсы не должны перезапускать контейнер.

## Обновление

Из каталога с исходниками:

```bash
git pull
cd deploy/compose
docker compose up -d --build
```

Схема базы обновится сама при запуске (`BABKI_AUTO_MIGRATE`). Перед
обновлением сделайте резервную копию (ниже) — откатить программу на старую
версию после обновления схемы можно только восстановлением копии.

## Резервная копия

Всё, что программа знает, лежит в одной базе Postgres. Копия — одной командой
из каталога `deploy/compose`:

```bash
docker compose exec -T postgres pg_dump -U babki -Fc babki > babki-backup.dump
```

Восстановить её в установку (та же версия программы или новее — миграции
догонят схему при запуске):

```bash
docker compose up -d postgres
docker compose exec -T postgres pg_restore -U babki -d babki --clean --if-exists < babki-backup.dump
docker compose up -d
```

`BABKI_ENCRYPTION_KEY` из `.env` храните вместе с копией, но не в одном
файле: без ключа токены брокеров в копии не расшифровать (их можно ввести
заново), а с ключом копия равна доступу к брокерскому счёту.

Журнал отдельного счёта можно выгрузить таблицей — «Выгрузить в CSV» над
журналом на экране счёта; тот же файл читается обратно через «Импорт из
файла».

## Демо-данные

Чтобы быстро посмотреть интерфейс без ручного ввода, на чистом инстансе
выполните:

```bash
docker compose exec app babki seed
```

Команда создаёт демо-семью со счетами и балансами и двух пользователей:
`demo` / `demo1234` (владелец) и `partner` / `demo1234` (редактор). Работает
только пока в базе нет данных — на непустом инстансе завершится ошибкой.

Заодно заводится выключенное демо-подключение Т-Инвестиций с парой прогонов
синхронизации, одним расхождением в сверке и несколькими неразобранными
операциями — чтобы раздел «Подключения» было на чём посмотреть. Токен у него
поддельный, и подключение выключено намеренно: в таком состоянии фоновая
синхронизация его пропускает, поэтому демо-стенд никуда не ходит по сети.
Включать его не нужно и незачем — включённое, оно раз в час будет пытаться
расшифровать несуществующий токен и писать об этом в лог.

Открыв брокерский счет, увидите позиции (количество, стоимость вложений,
рыночная оценка, прибыль, полученный доход), строку «Зафиксировано» с
результатом уже закрытых сделок и журнал операций с покупками, продажами,
дивидендами, купонами и переносом бумаг между счетами.

На `/accounts` карточка «Итого» показывает общий net worth в базовой валюте
семьи с разбивкой по валютам счетов; неконвертированные валюты и устаревшие
курсы честно помечены рядом с суммой, а не скрыты внутри неё. В деталях счета
позиции показывают рыночную оценку по последней котировке (MOEX, ЦБ РФ) с
датой — для FXUS и AAPL из демо-набора её нет, поэтому там честный прочерк,
а не ноль. Базовая валюта настраивается владельцем на `/settings`.

Переключатель «в валюте счёта / в базовой» в шапке приводит суммы счетов и
позиций к базовой валюте и обратно; выбор запоминается в браузере, а строки без
курса честно остаются в своей валюте с пометкой.

## Как считаются деньги

Правила — какие бумаги уходят при продаже, от какой страны они зависят, как
учитывается курс валюты, что такое «зафиксировано» и как считается бумага без
цены покупки — собраны в [docs/accounting.md](docs/accounting.md).
