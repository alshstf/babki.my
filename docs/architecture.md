# Как устроена программа

Один бинарь на Go, одна база PostgreSQL, интерфейс на React, собранный внутрь
бинаря. Здесь — где что лежит и на чём всё держится; как считаются деньги —
в [accounting.md](accounting.md).

## Роли процесса

`babki <роль>` (`cmd/babki`):

| Роль | Что делает |
|---|---|
| `all` | всё сразу: миграции, HTTP, фоновые задачи — обычный запуск дома |
| `api` | только HTTP; фоновые задачи лишь ставит в очередь |
| `worker` | только фоновые задачи |
| `migrate` | обновить схему базы и выйти |
| `seed` | создать демо-семью на пустой базе |
| `version` | версия |

## Модули

| Пакет | За что отвечает |
|---|---|
| `internal/family` | пользователи, пространство (семья), роли, вход и сеансы |
| `internal/account` | счета, отметки остатка, итог семьи, график капитала, доходность семьи |
| `internal/instrument` | каталог бумаг |
| `internal/operation` | журнал операций: запись, правка, удаление, переводы, проверка журнала перед записью |
| `internal/portfolio` | движок: позиции, партии, реализованная прибыль, оценка, доходность счёта и бумаги |
| `internal/marketdata` | цены (Мосбиржа, история), курсы ЦБ, металлы, пересчёт валют |
| `internal/corporateaction` | реестр сплитов, конвертаций и выделений и их применение к журналам |
| `internal/importer/tinvest` | подключение Т-Инвестиций: синхронизация операций, сверка, цены |
| `internal/importer/table` | импорт таблицы (CSV) и выгрузка журнала в CSV |
| `internal/export` | выгрузка всего пространства в JSON |
| `internal/platform/*` | общее: конфигурация, база и миграции, HTTP-сервер, фоновые задачи (River), деньги, даты, шифрование секретов |

Правило: модуль пишет и читает только свои таблицы, чужие данные — через
хранилище модуля-владельца; связи между модулями собираются в `cmd/babki`.
Ядро учёта — каталог (`instrument`), журнал (`operation`), движок
(`portfolio`) и реестр событий (`corporateaction`) — одно целое и делит свои
таблицы внутри себя; остальные модули ходят к нему через его хранилища.

У каждой таблицы есть модуль-хозяин; это проверяет тест `internal/archtest`
(`tables_test.go`): SQL с чужой таблицей роняет его. Оставшиеся пересечения
записаны там поимённо, с причиной, и список может только сокращаться: импорт
Т-Инвестиций соединяет свои таблицы с журналом, каталогом и счетами одним
запросом, журнал блокирует строку счёта на время записи, демо-данные
заполняют историю синхронизаций.

Модули лежат слоями, и зависеть можно только от своего слоя или нижнего:

| Слой | Пакеты |
|---|---|
| 0 | `internal/platform/*` |
| 1 | `family` |
| 2 | `instrument`, `marketdata`, `account` |
| 3 | ядро учёта: `portfolio`, `operation`, `corporateaction` (с каталогом `instrument` со слоя 2) |
| 4 | `importer/*`, `export` |
| 5 | сборка: `cmd/babki`, `internal/background`, `web` |

Это проверяет тест `internal/archtest`: зависимость вверх по слоям и пакет,
не поставленный ни на какой слой, его роняют.

## На чём всё держится

- **Журнал — единственный источник правды.** Позиции, стоимость, прибыль и
  доходность не хранятся, а каждый раз пересчитываются движком из операций
  счёта. Любая запись сначала прогоняет журнал счёта целиком и отказывает,
  если он перестаёт сходиться.
- **Деньги — целые числа в копейках/центах** (`int64`), без чисел с плавающей
  точкой; количество и цены — десятичные. Интерфейс деньги не считает, только
  показывает то, что дал сервер.
- **Очередь по дате покупки (ФИФО)**: при продаже и переводе уходят бумаги,
  купленные раньше.
- **Сначала контракт.** `api/openapi.yaml` — описание всех маршрутов; из него
  генерируются типы сервера и клиента (`make gen`).
- **Фоновые задачи** — очередь River в той же базе: обновление цен и курсов,
  история цен, синхронизация брокера, реестр событий. Как каждая закончилась
  последний раз, видно в «Настройки → Источники данных».
- **Секреты** (токены брокеров) хранятся зашифрованными ключом из
  `BABKI_ENCRYPTION_KEY`.
